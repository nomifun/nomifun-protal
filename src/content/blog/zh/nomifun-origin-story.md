2025年的时候，我在玩 小智AI机器人 ，当时仿照教程手搓了一个 “桌面宠物”摆件。

桌面宠物”摆件当然不能只是和我对话，最好还能帮我控制电脑、上网搜索、帮我监督我电脑上的claude code干活，所以开发了“糯米饭”的前身 ——“NomiFun Desktop”。一个完全本地的 AI 工作站，可以调整 桌面伙伴的形象，配置 语音、视觉、记忆、配置知识库、设置定时任务、并且 能够 监督 claude code 工作，远程连接上 “糯米（Nomi）”机器人，和手机端的 桌面程序。它的 **服务端 就是 直连用户自己的电脑**，不需要上云。这样用户的所有使用痕迹都在本地，用户想要带走甚至可以使用存储介质无损带走。

后来因为各种原因，这个业务小玩具就没再怎么推进了。

26年的时候，claude code 的代码水平开始达到了飞越，我们开始正式将 AI coding 应用到我自己的coding 的方方面面。

我们团队在进行工作开发中，需要管理大量的需求，并逐一投喂给AI 去写代码，彼时还是人工手动地一个个需求接力安排给 claude ，属实比较麻烦。

当时还没有出现 /goal 这些 loop 编程的设计。

我们团队内部的一个解决方案就是，**搭建了一个需求管理平台**，需求统一使用标签（Tag） 进行管理 与订阅，并设计了智能多agent多模型决策系统，来协助运行时需求推进、管理、拆分、调度分配。

当时靠这套方案自动托管了一个小app的生产开发，即便 后来 agent loop 工程出来，/goal 模式出来，这套方案依旧能够持续使用而不过时。

后来，openclaw 出现了现象级的爆火，受 openclaw的启发，我们对我们的桌面伙伴进行了升级，让他除了支持机器人的连接外，还能够支持各种 im channel 的连接。

讲到这里，糯米饭（NomiFun） 的“桌面伙伴” 和市面上所有的 “桌宠” 其实是完全不同的设计，它不是一个摆件，他是一个实实在在的 agent，能够工作、具有独立的记忆，能够挂载多个知识库，具有无限会话记忆、独立的、自进化 skill 能力，以及多个“伙伴”的记忆共享、skill 共享能力。同时它拥有 糯米饭（NomiFun） 全平台的能力，包括 computer use 和 browser use 能力。最重要的是，它的 im channel 每个伙伴可以绑定多个，并且NomiFun 平台可以创建并同时存在多个 “桌面伙伴” 。这些设计在当时都极为领先，且体验友好。

我们也是在这个时候，意识到身边朋友对它的喜欢，所以开始筹备了NomiFun 的开源事项。我们期望开源一个 完全运行在用户本地，部署和使用都很简单，并且能够能够承载我们很多超前设计理念功能的产平。

重构的第一步就还比较波折和困难的：

1. UI 早期只是够用，但是比较丑，需要重构；
2. 整体使用的 electron 框架，打包体积大，资源占用高，GC 的问题不适合长期进行运行，需要换技术方案；
3. 积累了很多历史重设计功能，有些功能的服务端在云上，不完全是在本地。比如“统一需求管理平台”、“统一云文档知识库”等等……需要把所有云功能都删除掉，或者重构掉；

当时前前后后改造了接近两个月，终于在端午节（2026年6月19日）偷偷开源了出去，取名为“NomiFun”，中文名为“糯米饭”。（后面又撤回调整了一版，正式开源时间是 2026年6月25日）。

之后就是大家所见的各种迭代了，不过近期也是意识到了后续的一些迭代发现的不足，在进行底层重构，导致了产品功能稳定性不如 0.1.x 系列版本稳定，如果稳定的时候，我们会将版本号调整为 1.x.x。

我们对于这个产品实际上**没有任何 商业化 的追求**，未来也不会有，我们只是想做一个有意思的产品，不一定是好用。毕竟我们很清楚自己的处境，满打满算只有一个人负责研发这个产品，要做一款很好用很牛逼的产品还是很困难的。所以我们选择开源的另外一个初心就是，希望能够引入新鲜的、热心的朋友们加入进来，一起共建这个项目，让他能够很出彩。

在openclaw 火的时候，我们的产品已经有很不错的用户反馈了，后来在 0.0.1版本上线后，我们在仅有的私域 社群里，便收到了大量 用户们的赞美，当时的功能尚且比较稳定，并且有大量业内没有的创新能力，并且体验上比很多商业化产品要很很多。当然这里也需要道个歉，后来在进行重构的时候，破坏性地重构确实导致了我们这个产品功能稳定性大幅度地下降，我们将在后续持续修复 和优化回来，尽可能早点推出稳定版。

我们后来陆续推出 “智能客服”、“跨平台小程序” 等功能，也同时开源了 其他的开源项目源码，包括 “手机APP”、“小智AI固件适配版”、“网络中继器”，大家可以猜猜我们接下来将推出的 开源产品矩阵 /坏笑 。

这里面也**重点介绍一下我们的 “手机APP”** 的开源产品设计，框架并不是什么新框架React Native 本身不是最有，只是一个快速开发的方案而已。我们真正想介绍的，是我们的手机 直连 NomiFun Desktop 的设计。我们一直在强调 用户隐私、数据安全，当用户的手机终端直连电脑，不经过任何第三方中继器的时候，这个时候，从响应体验、用户信息安全而言，保障性更好， 并且也由于这个设计，我们的手机APP 不用承载太多的功能代码开发，不需要维护太多的服务端逻辑。

另外也介绍一下我们的 **“跨平台小程序”**，目前还只是一个预览版，这是目前比较领先agent 产品的设计思想，先给大家尝鲜，我们会持续打磨。 我们想要做一个 **用户喜欢的、可自进化的 Agent、可迁移的agent**，其中有一些重要的能力：

1. 自己生产 可执行 程序，自己调用自己的程序；
2. 自己发布、传播自己生产的程序；

其实很多用户用AI coding 工具，要么是工作，要么就是做自己的程序。我们在想，传统的软件工程从开发、编译调试、部署运行 的这些过程，即便有ai的情况下，目前对于用户而言，依旧不是那么友好。

对于 自进化 agent 而言，能够在运行时 自己给自己创造工具，加载工具非常重要；

对于用户而言，能够有所用即所得，并且可以持续使用、持续迭代的产品功能体验也非常重要；

所以设计一个运行时环境很重要，我们正在做这一步，这个设计其实和 docker、jvm 的这些思想很想，放入即可装载执行，并且可以动态更新升级，并且跨平台可用。目前 NomiFun 受限于当前的技术栈架构设计原因，“小程序”功能其实远没有达到自己的预期，我们将在后续新开辟一个开源项目提供给大家，尽可能不破坏 NomiFun-desktop 的能力交互。
