知识库是 NomiFun “config one, use anywhere” 的内容底座：你可以维护一份本地 Markdown 目录，把它挂载到会话、终端、工作目录或伙伴，让任意 Agent 按明确的检索协议**先查再答**。

> 入口：左侧边栏 **知识库**（路由 `/knowledge`）。当前版本的具体界面和回写选项，以应用内页面为准。

## 知识来源

1. **本地 Markdown**：适合手册、规范、项目笔记和团队资料。
2. **URL 快照**：创建时抓取公网网页并转为 Markdown；支持持久化 Snapshot 与运行期 Live 模式，并带 SSRF 防护。
3. **飞书 Feishu**：连接器能力按当前版本逐步开放。

> **Notion 来源仍在路线图上**，不要把它当作当前公开能力。

## 基本操作

1. 在知识库页创建一个库，填写名称与描述并选择本地 Markdown 目录。
2. 按需添加 URL 来源，选择 Snapshot（保存一份稳定快照）或 Live（每次运行时获取最新内容）。
3. 为知识库生成描述与摘要，帮助 Agent 判断“什么时候应该查阅”。
4. 将知识库绑定到会话、终端、工作目录或伙伴。
5. 在会话中确认 Agent 是否先检索，再根据检索结果回答或执行。

## 回写策略

当前版本不应再简单理解成“所有 IM 写入都永远进入 `_inbox`”。实际策略由知识库挂载点和应用版本决定，常见模式包括：

- **Disabled（关闭）**：不允许 Agent 回写。
- **Manual（手动）**：关闭回合结束时的自动抽取；只有你在当前会话明确要求 Agent 记录、保存或记住内容时，才会执行知识写入。
- **Auto（自动）**：允许 Agent 在回合结束时判断并自主沉淀有长期价值、可复用且确定性较高的内容。

这些模式都不是统一的 `_inbox` 暂存流程；符合条件的写入会落到知识库正文。更新已有文档时，应用采用追加与 compare-and-swap 等保护，尽量避免静默覆盖和并发冲突。外部 IM 渠道是否允许回写还由 `channel_write_enabled` 单独控制，开启后同样写入正文。重要资料仍建议纳入版本控制并定期备份。

## Agent 如何使用知识

知识库会挂载进工作区的受控路径。注入上下文包含库的描述、摘要、目录提示和检索协议；内置 Nomi、ACP Agent、终端中的 CLI 与伙伴都可以使用同一套知识能力，具体可见范围由绑定作用域决定。

URL 抓取只接受 `http/https`，内网和回环地址会受到 SSRF 防护限制。调用外部 URL、模型或渠道时，数据会按你配置的供应商与连接策略处理。

## 常见问题

**知识库会不会自动把所有对话保存下来？**
不会。是否回写取决于知识库策略和 Agent 的判断；你可以关闭回写，使用手动模式只在明确要求时写入，或使用自动模式让 Agent 按较高门槛自主沉淀。

**一座知识库能给多个会话使用吗？**
可以。按工作目录或伙伴绑定后，多段会话可以共享同一知识库；也可以只挂载到单个会话。

**Notion 什么时候可用？**
它属于持续布局中的方向，当前公开版本请以应用内可见来源为准。
