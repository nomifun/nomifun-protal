会话工作区是你和伙伴一起干活的主战场。每段会话都有自己**独立的工作目录**，页面把消息流、文件树、预览面板和一个挂载到该目录的终端集中在一处——选好 agent 与模型、按需挂上知识库、必要时交给自动工作，全程不离开这一个界面。

新建会话后会进入 `/conversation/:id`。从侧边栏点"新会话"，或在首页 `/guid` 选好 agent、模型与提示词即可创建。

![会话工作区布局](/images/zh/02会话/会话.png)

## 操作步骤

1. **选 agent 与模型。** 在首页或会话头部选择后端：内置 **Nomi** 无需额外安装，最适合首跑；也可选 Claude Code、Codex、Gemini、Qwen、OpenCode 等外部 CLI（这些需先在宿主机装好对应 CLI）。对支持切换的 agent，再选 provider 与 model id。
2. **认识界面四件套。** 会话页通常包含：
   - **消息流**——模型回复、工具调用、文件变更与执行状态。
   - **文件树**——本会话工作目录中的文件，随 agent 的读写实时变化。
   - **预览面板**——直接预览代码、Markdown、PDF、Office、HTML 以及 diff。
   - **终端**——一个挂载到工作目录的 PTY，可与会话并排操作同一份文件。
3. **挂载知识库（可选）。** 在会话内把已建好的知识库挂进来，**会话里的 agent**（不论 nomi、ACP Agent 还是终端 CLI）回答时即可引用其中内容。来源以**飞书 Feishu 连接器**与 **URL 实时快照**（带 SSRF 防护）为主。

   ![为会话挂载知识库](/images/zh/02会话/会话挂载知识库.png)

4. **开启自动工作（可选）。** 想把一批需求交给会话无人值守地逐条处理，就在会话头部打开 **AutoWork** 控件：选一个 tag、设可选的完成上限、启用。编排器随即按 `pending → in_progress → done` 认领并执行。这是绑定 tag 的标准入口。

   ![在会话内开启自动工作](/images/zh/02会话/会话开启自动工作.png)

5. **加一层决策值守（可选）。** 对要长跑、无人盯守的会话，在**同一处头部**打开 **IDMM**（智能决策）：它在 provider 抖动或决策卡点时让本轮继续存活，护送到终态而不是超时。详见下方"相关"。

## 要点与边界

- **每段会话工作目录独立**——文件树、预览与终端都围绕这一个目录展开，会话之间互不串扰。
- **预览覆盖常见格式**——代码 / Markdown / PDF / Office / HTML / diff 都能直接在面板里看，不必另开外部程序。
- **终端默认挂在工作目录**——它与消息流操作的是同一份文件，适合手动检查或运行命令补位。
- **记忆是共享的，技能按伙伴隔离**——全体伙伴共享一条记忆采集 / 学习链路，但每个伙伴的**技能库**相互独立。按伙伴细分的私有记忆敬请期待。
- **故障值守与决策值守默认关闭**——需要时在会话头部手动开启；可触发模型 failover 队列（最多 4 次切换）。
- **知识库来源**——飞书 Feishu 连接器已实现；Notion 接入为路线图，尚未支持。

## 常见问题

- **会话和终端是同一个工作目录吗？** 是。会话内的终端默认挂载到该会话的工作目录，所以你在终端里看到、改到的就是文件树里那份。
- **预览能改文件吗？** 预览面板用于查看（含 diff 对比）；文件的写入由 agent 或终端完成，你在面板里实时看到结果。
- **不开自动工作可以吗？** 完全可以。AutoWork 与 IDMM 都是可选项，默认关闭，普通交互式会话无需开启。
