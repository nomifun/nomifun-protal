# 门户字体、组件与环境审查

日期：2026-10-02。审查基线为本轮修正前的旧版源码，已随 Git 历史重建移除。产品目标：在保留简洁、高留白、丰富参考动效的基础上，让普通读者在正常缩放下读懂内容、看清操作。

采用 Product Design audit 流程，先截图、测量当前展示，再实施和对照。以下证据均在本轮采集，未把上一轮验收图或记忆当作当前视觉证据。截图存于 `qa/readability/`，对照图为 `readability-comparison.png`。

## 总体判断

主标题的尺度基本合适，问题主要是正文、操作和限定说明被局部规则压到8–13px，灰色文字再叠低透明度。大舞台与小字之间失衡，导致重要能力和操作看起来像装饰。中文版与英文版还有不同的晚覆盖规则，使仅提高全局body字号无法解决问题。

现有大留白、首屏标题、圆角与柔和色域、章节递进及互动机制是优点。本次保留这些设计，以正文／控件／辅助信息分级调整，避免把微型图形里的纯装饰序号和终端字符都强制放大。

## 字体与色彩体系

- 原WOFF2元数据：Regular为静态400，Medium为静态500，无可变字体fvar；原CSS把Medium声明为500–800。已纠正为真实500，保留本地品牌字体，并明确中英文系统回退；未引入远程字体服务。
- 正文以桌面16–20px／手机14–17px分级，控件约12–16px、辅助约12–13px。固定场景优先更合理的空间与真实内滚，不整体scale压小内容。
- 按卡片色系配置深浅文本，重要正文取消低opacity。深色视频/工作卡仍用浅色文本，保持明暗章节身份。边框、圆角和图形比例沿用原设计。

若要以可衡量标准评估普通文字，目标是至少4.5:1，大字至少3:1；纯装饰与标志另有适用边界。[W3C对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。以下是明确CSS不透明前景／纯色背景的计算，并非整站、动态shader、SVG或实体显示器的合规证明：

## 验证与限制

- 当前源码最终生产构建成功，25个HTML、24个内容地址。`check:content`、`check:i18n`继续检查双语内容、资源、锚点及英文展示。
- 浏览器覆盖1440×900、390×844、320×740和390×650，检查了主要正文、控件、内部滚读、语言和实际动态状态。
- 保留双波空间、翻牌、液态导航、伙伴落牌、工作横轨、创作压栈和弧形轮盘；字体修正没有重新加入全站方括号鼠标。
- 没有把源码颜色计算扩大为完整WCAG认证；实体触控、读屏软件、跨操作系统字体与性能基准仍未执行。
- 工作视觉区、创作和架构在小窗口需局部滚读，这是用正常字号保留完整说明的取舍；并没有宣称小视口可同时展示所有内容。

审查重点的字体、对比与遮挡问题已修正，主要阅读/导航/互动在上述浏览器范围通过。当前改动集中在三个最终导入的polish层、真实font-face及相应组件的溢出/导航逻辑，便于维护。
