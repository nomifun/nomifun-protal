# 手机内部滚动排查与修复

日期：2026-10-09。目标是在手机浏览官网时，让普通内容与演示图景的纵向手势交给页面，同时保留可读字号、图景比例、卡片色板和交互功能。

本文保留提交 `d8f789e` 的历史验收。该版本将手机工作、创作、技术舞台改为静态阅读，导致原有主要动画缺失。当前方案已恢复手机滚动舞台，并继续消除图景内部滚动，见 [手机动效恢复验收](mobile-motion-qa.md)；本文的静态布局描述不再代表当前实现。

## 当前证据与成因

本轮使用 Codex 内置浏览器运行当前源码和最终静态导出，截图与 DOM 测量均来自本轮。390×844 英文首页基线发现 12 处内部纵向滚动：5 张工作卡、Chat / Audio / Canvas 3 个创作演示、4 个技术设计面板。工作卡和创作卡仍固定为一屏，正文与图景增大后剩余空间不足，`overflow-y: auto` 承接了超出的内容；技术面板另有 JS 持续写入固定舞台高度。内部区域随后被标记为 `data-lenis-prevent`，页面手势落入内层。

没有通过隐藏滚动条、裁掉内容或整体缩小演示解决问题。工作、创作和技术设计在 `<=1000px` 使用内容自然高度；普通展示内容不再承担内部纵向滚动。圆角、票券切边和装饰层仍保留原本的局部裁切用途。

工作与创作导航使用真实章节坐标定位，不假定手机卡片等高。桌面粘性卡片仍使用等高间隔定位，从 Canvas 返回 Image 的实际位置误差为 0.203125 CSS px。

自然高度区域通过 ResizeObserver 合并到一帧发送 `portal:layout`，让收据展开、画布变化和技术视角切换之后的页面动画位置重新测量。工作舞台销毁时先关闭时钟写入，再清理它拥有的变换，避免 GSAP revert 的回调把桌面位移写回手机卡片。

## 尺寸与状态验收

中英文首页分别验证 320×568、360×667、390×844、430×932、768×1024、844×390、1000×700，共 14 次。最终所有尺寸的普通首页内容：内部纵滚 0、内部横滚 0、Lenis 拦截标记 0，document scrollWidth 与 clientWidth 相同。

动态状态覆盖：收据展开、需求写入授权、聊天工具选择、画布加入音频，以及全部 4 个技术视角。320px / 390px 两种语言均通过。

跨断点验证 390 → 1366 → 1000 → 1001 → 768 → 1440 → 320。每次返回手机布局后，工作轨道与首卡的 inline transform 均清空，创作卡回到 relative，技术舞台的 inline height 清空，普通内容拦截标记为 0。回到桌面后原粘性舞台恢复，非当前工作卡的 inert 恢复。

桌面回归覆盖中英文 1366×768、1440×900、1920×1080：原工作、创作、技术舞台保留 sticky；创作 5 个模式的 clientHeight 与 scrollHeight 相同。桌面工作与技术面板原有的短空间后备滚动策略保留，本次修复针对手机及窄屏阅读。

## 本地检查与边界

- `npx next build`：成功静态导出；本轮不需要更新下载发布快照，因此直接执行 Next 构建，未调用会同步外部版本元数据的 prebuild。
- `npm run check:content`：40 HTML、995 站内链接/锚点、991 资源引用通过。
- `npm run check:i18n`：26 英文页（含别名）、13 中文页及 26 规范 sitemap 地址通过。
- `npm run check:work-motion`：标准桌面的阶段居中、入场顺序、连续性、端点及逆向遍历通过。
- 修改文件的 Prettier 与 `git diff --check` 通过。

本轮证据是内置浏览器的移动 CSS 视口、真实页面布局、控件交互与页面滚动，未使用真实 iOS / Android 设备，也未模拟系统减少动画设置。减少动画的连续阅读样式、导航定位和监听清理由源码审查确认；这些不构成实机触摸或完整无障碍认证。
