# 中英文维护规则

支持 `zh`（简体中文）和 `en`（English），默认英文。英文规范URL为 `/`、`/products` 等根路径；`/en`、`/en/products` 等英文别名也可直接访问，canonical统一指向对应根路径。中文URL为 `/zh`、`/zh/products` 等对应路径；`x-default` 指向规范英文页面。sitemap收录13个规范英文页面和13个中文页面，不重复收录英文别名。

## 文档与语言入口

`app/(zh)/zh` 和 `app/(en)` 使用各自根文档，通过 `components/i18n/DocumentLayout.jsx` 共用结构。`app/(en)/en` 提供显式英文别名，根路径页面复用同一组英文包装页。全部页面在静态HTML中已包含对应语言，具有独立的 `html lang`、title、description、OG locale、canonical 与 hreflang。

语言切换使用普通链接，保留当前页面、query与hash。两个根文档之间整页加载，使页面语言与元信息同步。该行为遵循 [Next.js Route Groups 的多根布局规则](https://nextjs.org/docs/app/api-reference/file-conventions/route-groups)。页面语言完全由URL决定；旧的浏览器语言偏好不再参与跳转，也不再读写。`/` 与 `/en` 始终为英文，`/zh` 始终为中文，浏览器存储不可用或JavaScript未执行时也保持该规则。

统一双语404使用当前Next 15.5的 `experimental.globalNotFound`，因为多根布局不会自动套用一个共用错误文档。404为noindex，并提供明确的中文／英文首页恢复入口，不自动猜测缺失页面的翻译。

## 文案与链接

- Client组件：`useLocale()` 返回 `{ locale, t, path, asset }`，文本写 `t("原中文", "Natural English")`。可见文字、ARIA、alt、placeholder、动态状态、计数、SVG text都要有英语对照。
- Server页面：`createI18n(locale)` 使用同一规则，英文薄包装页显式传 `locale="en"`。元信息使用 `pageMetadata` 或各页已有metadata helper。
- React状态和数据键使用稳定值。已有中文内部key只作为判断，不直接展示；不要把翻译后的标签当作状态键。
- Next站内链接用 `components/i18n/LocaleLink.jsx`；原生绝对内链用 `path()`。`#anchor`、外链、mailto和共享素材地址按原用途保留。
- 产品数据由 `getProducts(locale)` 提供，社媒使用 `getSocialLinks(locale)`；真实仓库、邮箱和设备名称不另造。

英语应自然简洁。固定尺寸的图形、dock和tab优先短标签，完整解释放在正文中；不要通过整体scale压小文本来容纳翻译。手机过长内容允许局部滚读，只对实际可滚区域启用Lenis例外。

## 博客与素材

中文文章位于 `content/blog/*.md`，英文位于 `content/blog/en/*.md`，相同文章使用相同slug。`getPosts(locale)` 严格读取对应目录，不静默回退中文；新增文章应同时完成两种正文及frontmatter。英语日期使用英语格式。历史起源文章的中文品牌名以 `lang="zh-CN"` 标记，归档声明保持。

`localizeAsset` 集中映射三个需要英文UI的图片。品牌插画、原生图形几何与真实设备视频可共用；图形内部文字、视频标题、说明与可访问名称本地化。英文图片的真实来源、版本及测试数据性质见 [english-assets.md](./english-assets.md)。历史业务输入中的中文prompt不是界面漏翻，不修改真实截图中的用户内容。

## 验证

```powershell
npm run build
npm run check:content
npm run check:i18n
```

静态检查覆盖全部双语内容路由、资源、锚点、英文文本/ARIA、语言链接、元信息、sitemap及路径helper。浏览器应另外检查动态状态、语言往返、菜单、内层滚动和长文案在桌面／手机的布局。当前实际记录见 [i18n-qa.md](./i18n-qa.md)。
